# قاعدة البيانات: التشغيل والاختبار

**الحالة (2026-11-13):** `schema.sql` اشتغل على PostgreSQL 16.16 (Postgres.app) بدون أخطاء، و`tests/run.sh` يعدي كامل (209 فحص).

## الجهاز المحلي للتطوير
- **السيرفر**: Postgres.app 2.9.7 (PostgreSQL 16) منصّب بـ `~/Applications/Postgres.app` (موقّع ومُوثّق من Apple).
- **بيانات الاختبار**: مجلد `database/.pgdata` (يتحذف بدون ضرر)، على المنفذ **5544**، بدون كلمة سر وعلى `127.0.0.1` فقط.

```bash
PGBIN=~/Applications/Postgres.app/Contents/Versions/16/bin
# تشغيل السيرفر
$PGBIN/pg_ctl -D database/.pgdata -o "-p 5544 -c listen_addresses=127.0.0.1 -c unix_socket_directories=/tmp" -l database/.pgdata/server.log start
# إيقافه
$PGBIN/pg_ctl -D database/.pgdata stop
```

## تشغيل الاختبارات
```bash
database/tests/run.sh
```
يعيد بناء قاعدة `clinic_test` من `schema.sql` (يحذف القديمة)، ثم يشغل بالترتيب:
1. `tests/helpers.sql`: أدوات الاختبار + **وصفات العمليات الحساسة** (حجز، دفع، رقم وصل، صرف مخزون، صرف من الخزنة). هذي الوصفات المرجع لكود NestJS لاحقاً.
2. `tests/fixture.sql`: بيانات أساسية (فرع، موظفين، خدمات، طرق دفع، شفت، خزنة، مادة).
3. `tests/constraints.sql`: كل قيد عمل يفشل بنفس SQLSTATE المتوقع والصحيح ينجح.
4. `tests/race.sh`: عمليات متوازية حقيقية (جلسات psql منفصلة).
5. `tests/final.sql`: `v_integrity_checks` لازم يرجع صفراً، وأرقام الوصل بلا فجوات.

للتجربة على نسخة معدلة من المخطط: `SCHEMA=/path/mutated.sql database/tests/run.sh`. جربنا 3 تعديلات تخريبية (حذف فهرس الدفع المزدوج، حذف CHECK الخزنة، حذف CHECK الدفعة) والاختبارات كشفت كل واحدة.

- دفع مقابل إغلاق شفت، واسترجاع مقابل تأكيد الممرض (قفل على مستوى التطبيق، يتختبر مع كود الخادم).
- الحمل الكبير والأداء، وPostgreSQL 15.
- الصلاحيات (revoke على الجداول) والنسخ الاحتياطي والاستعادة.
- حسابات الأسعار والخصم والنقاط نفسها (كود الخادم). هنا نختبر قيود البيانات والأمثلة الحسابية بس.

## ملاحظات للكود الخادم (من الاختبارات)
- **أعد المحاولة عند `40P01` (deadlock) و`40001`**: لما عمليتين تكتبان عرضين متداخلين بنفس اللحظة، قيد الـ exclusion يرفض الخاسر أحياناً بـ `23P01` (تداخل) وأحياناً بـ `40P01`. النتيجة وحدة، بس المعاملة لازم تنعاد.
- **ترتيب القفل**: الزبون ← الزيارة/اليوم ← الجلسة/الكشفية ← الشفت ← الخزنة/المخزون.
- **أي خطأ بمعاملة الدفع أو الحجز يتراجع كله** (المقعد والرقم والوصل)، فلا حاجة لتنظيف يدوي.
