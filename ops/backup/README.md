# النسخ الاحتياطي والاسترجاع

**الهدف**: إذا ضاع السيرفر أو انحذف شي بالغلط، نرجع النظام كامل بخسارة **أقصاها 5 دقايق**، والنسخ **مشفرة** ولا يفتحها غير المالك.

## 1. شنو ينحفظ، وين، ومنو يملك شنو

| الشي | شلون | كل كم | وين |
|---|---|---|---|
| **قاعدة البيانات** (كل شي: زبائن، وصلات، خزنة، رواتب...) | نسخة كاملة (`pg_basebackup`) | يومياً 3 الفجر | التخزين البعيد |
| **سجل التغييرات (WAL)**: هذا اللي يخلي الخسارة 5 دقايق | يتنسخ لمجلد انتظار فوراً، ويتشفر ويترفع كل دقيقة | مستمر | التخزين البعيد |
| **تفريغ منطقي** (`pg_dump`): شبكة أمان، ينفتح على أي إصدار PostgreSQL، ويسمح باسترجاع جدول واحد | يومياً | يومياً | التخزين البعيد |
| **الصور** (إثبات مالي، قبل/بعد، الشعار) | يرفع الجديد فقط | كل ساعة | التخزين البعيد |
| **المفتاح الخاص للتشفير** | يتولد مرة وحدة | — | **عند المالك فقط** (مو على السيرفر ولا بالسحابة) |

كل ملف يتشفر قبل ما يطلع من السيرفر: كل ملف بمفتاح AES-256-GCM خاص فيه، والمفتاح يتغلف بمفتاح RSA-4096 **العام**. السيرفر يملك العام بس، فحتى لو انسرق السيرفر أو حساب التخزين السحابي، النسخ ما تنفتح.

**التخزين البعيد**: عند شركة غير شركة الاستضافة (حتى لو انغلق حساب الاستضافة تبقى النسخ). عبر `rclone` يشتغل مع أي تخزين S3: Backblaze B2، Wasabi، Hetzner Storage Box، AWS... (مثال بالأسفل). ونسخة أسبوعية إضافية عند المالك على قرص خارجي (`BACKUP_REMOTE=dir:/Volumes/Backup/clinic`).

**الاحتفاظ**: آخر 7 أيام + آخر 4 أسابيع + آخر 12 شهر (يتغير بالمتغيرات). تنظيف تلقائي. (السجلات الطبية والمالية بالنظام نفسه تبقى للأبد، هذا عمر النسخ الاحتياطية فقط.)

**المراقبة**: كل مهمة تسجل حالتها، وشاشة **الرئيسية عند المالك** تعرض بطاقة «النسخ الاحتياطي»: أخضر أو مشاكل بالعربي (نسخة قديمة، رفع متوقف، فحص استرجاع قديم...). وإذا ضبطت `BACKUP_ALERT_COMMAND` تنرسل رسالة فورية عند أي فشل.

## 2. التنصيب (مرة وحدة)

### أ) المالك يولّد المفاتيح على جهازه (مو على السيرفر)
```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 -aes-256-cbc -out backup-private.pem   # يطلب كلمة سر: اختر قوية
openssl pkey -in backup-private.pem -pubout -out backup-public.pem
```
- **`backup-private.pem` + كلمة سره**: عند المالك فقط. خزّنهم بمدير كلمات مرور، ونسخة مطبوعة بمغلف مختوم بمكان آمن. **ضياعهم = ما أحد يقدر يفتح النسخ (حتى أنا)**.
- **`backup-public.pem`**: هذا بس يروح للسيرفر/الفني.

### ب) على السيرفر
1. انسخ `backup-public.pem` لـ`/etc/clinic/` وجهّز `/etc/clinic/backup.env` من `backup.env.example` (فيه كل الشرح).
2. جهّز حساب القاعدة: `psql -f setup-db-role.sql` وضبط `pg_hba.conf` (التعليقات داخل الملف).
3. أضف `postgresql-backup.conf` لإعدادات PostgreSQL وأعد تشغيله **مرة وحدة**.
4. مجلدات: `sudo install -d -o postgres -g clinic -m 2775 /var/lib/clinic-backup/spool` و`sudo install -d -o clinic -m 750 /var/lib/clinic-backup/{state,work}` (يكتب الأرشيف `postgres`، ويرفعه `clinic`).
5. rclone: `rclone config` وسمّ الريموت `offsite` (مثلاً Backblaze B2: أنشئ Bucket خاص + مفتاح تطبيق للـBucket فقط، وفعّل «Object Lock/Versioning» إذا متاح لحماية من الحذف).
6. فعّل المؤقتات: `sudo cp systemd/* /etc/systemd/system/ && sudo systemctl enable --now clinic-backup-ship.timer clinic-backup-daily.timer clinic-backup-uploads.timer`.
7. شغّل أول نسخة يدوياً: `sudo -u clinic env $(cat /etc/clinic/backup.env | xargs) node /opt/clinic/server/dist/cli/backup.js daily` ثم افتح الرئيسية عند المالك: لازم تشوف البطاقة تتحول لسليم خلال دقايق.
8. **جرّب الاسترجاع قبل ما تعتمد عليه** (القسم 4).

> **الحالة**: الأدوات والاسترجاع الزمني انفحصت على PostgreSQL حقيقي بسيناريو كارثة كامل (راجع القسم 6). ملفات `systemd` وربط `rclone` الفعلي مع تخزين سحابي حقيقي **ما اتجربوا** (ما أكو سيرفر Linux ولا حساب تخزين هنا): جرّبهم بالخطوة 7 و8 بأول تنصيب.

## 3. الاستخدام اليومي (ما تحتاج تسوي شي)
المؤقتات تشتغل لحالها. المالك يراقب البطاقة بالرئيسية، والفني يستلم التنبيه إذا فشل شي.

أوامر يدوية (على السيرفر، بنفس بيئة `backup.env`): `node dist/cli/backup.js` مع: `status` (صحة النسخ JSON)، `daily`، `ship`، `base`، `uploads`، `prune`.

## 4. فحص الاسترجاع الشهري (مهم: نسخة ما انجرب استرجاعها ما تنحسب نسخة)
يحتاج المفتاح الخاص، فيشتغل **على جهاز المالك أو الفني بحضور المالك** (مو على السيرفر). يسترجع آخر نسخة + كل WAL بمجلد مؤقت، يشغل PostgreSQL عليه (بدون شبكة)، يفحص سلامة النظام (`v_integrity_checks` لازم صفر)، يمسح كل شي، وينشر النتيجة للتخزين فتظهر ببطاقة المالك:
```bash
export BACKUP_REMOTE=rclone:offsite:clinic-backups/jasmine  BACKUP_PRIVATE_KEY=~/keys/backup-private.pem  BACKUP_PRIVATE_KEY_PASSPHRASE='…'
export DATABASE_URL=postgres://clinic_backup@localhost/clinic   # للأسماء فقط (اسم القاعدة والمستخدم)
node dist/cli/backup.js verify
```
إذا ما انعمل 35 يوم تظهر البطاقة تنبيه أصفر.

## 5. الاسترجاع (الكوارث)

كل الأوامر على السيرفر **الجديد أو المصلّح**، والمفتاح الخاص يجي مع المالك (`BACKUP_PRIVATE_KEY`). متغيرات `BACKUP_REMOTE` و`PGBIN`... نفس `backup.env`.

### أ) السيرفر ضاع بالكامل (أو انحذفت القاعدة)
1. نصّب PostgreSQL (نفس الإصدار الرئيسي) والتطبيق على سيرفر جديد (ما تشغل التطبيق بعد).
2. جهّز مجلد بيانات من آخر نسخة + كل سجل التغييرات لآخر لحظة:
   ```bash
   node dist/cli/backup.js restore --target /var/lib/postgresql/16/clinic_restored
   ```
3. شغّل PostgreSQL على المجلد (`pg_ctl -D … start`): يكمل الاسترجاع تلقائياً من التخزين ثم يصير جاهز (دقايق).
4. تأكد من البيانات (آخر وصل، الخزنة)، وشغّل التطبيق، وأعد تفعيل الأرشفة (`archive_mode`) بإعدادات القسم 2.
5. الصور: `node dist/cli/backup.js restore-uploads --target /var/lib/clinic/uploads`.
6. ثبّت `.env` (الأسرار) من نسختك: **`TOTP_ENC_KEY` لازم نفسه** وإلا المالك يعيد تفعيل التحقق الثنائي.

### ب) صار خطأ بشري (انحذفت بيانات الساعة 10:30 مثلاً) → رجوع للحظة قبلها
```bash
node dist/cli/backup.js restore --target /var/lib/postgresql/16/clinic_pitr --time "2026-11-14 10:29:00"
```
الوقت بتوقيت العيادة (بغداد) إذا ما كتبت فرق توقيت، أو اكتب `+03`/`Z`. يختار تلقائياً أحدث نسخة كاملة قبل هذا الوقت ويعيد سجل التغييرات لحد اللحظة. شغّله **بجنب** القاعدة الحالية على منفذ ثاني، واسحب منه البيانات الضايعة (مثلاً `pg_dump -t` للجدول) بدل ما تستبدل القاعدة الشغالة.

### ج) جدول أو سجل واحد من التفريغ المنطقي
فك تشفير `logical/<التاريخ>.dump.enc` (بأداة التشفير نفسها) ثم `pg_restore -t الجدول`.

### د) فك ملف يدوياً
(مثلاً للتحقق) `decryptFile` بـ`src/ops/backup/crypto.ts`، أو افحص أن الملف سليم: أي تعديل أو تلف يفشل الفك برسالة واضحة، ولا يطلع ملف ناتج.

## 6. شنو انفحص (وشنو لا)
**انفحص تلقائياً (اختبارات)**: التشفير (تلف أي بايت، مفتاح غلط، ملفات كبيرة)، سياسة الاحتفاظ والتنظيف (بأرشيف مصطنع بحالات كثيرة)، أرشفة WAL (متينة، إعادة، تعارض)، الرفع مع التحقق وفشل التخزين، نسخ الصور، حساب الصحة وحدودها، فهم أوقات الاسترجاع، وصلاحية شاشة المالك. **وسيناريو كارثة كامل بـPostgreSQL حقيقي**: بيانات + نسخة كاملة + تغييرات بعدها، تدمير الكلستر كله، استرجاع للحظة زمنية دقيقة (قبل صف أضفناه) ولآخر نقطة، استرجاع الصور، فحص الاسترجاع، التنظيف ثم استرجاع بعده. وتخريب عمدي للكود لكل جزء.
**ما انفحص**: ملفات `systemd`، `rclone` مع تخزين سحابي حقيقي، PostgreSQL على Linux (جربنا macOS)، وحجوم كبيرة (أرشيف بجيجابايتات)، وقت الاسترجاع الفعلي لقاعدة كبيرة.
